- Ask monitoring: each app Ask request records a "started" entry, so a request cut off mid-answer shows up as started with no outcome, and an "unavailable" answer now records the bounded reason (timeout or the failure message).
- Admin Ask Health view (Settings > Ask Health, admins only; `GET /api/admin/ask-health`): answers by model (complete, fell back, failed, cut off, median time, sources), the latest problems with their reason, today's free budget and Claude's status. Built from `ask_events`, so it never shows questions, answers or readers.
- DeepSeek V4 answers now reason at "low" effort (it defaults to "high", which took a study answer to about 60 s and past its deadline, so the reader got the "couldn't produce a source-checked explanation" fallback), and a streamed app answer has 90 s instead of 55 s (the app waits 130 s).
- Faster study answers: the research plan is written while the classes are searched (not after), and without the model thinking first (DeepSeek V4 `reasoning_effort: "none"`, Gemma 4 `enable_thinking: false`); a failed search still waits for the plan's metered call before the request is settled.
