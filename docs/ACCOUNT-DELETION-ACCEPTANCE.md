## Writer inventory boundaries

- In this server, `firestore-admin.ts` writes deletion barriers, fences and conditional cleanup operations. Browser/native sync writes use Firebase client rules. `published-studies.ts` and `account-links.ts` include conditional SQL barriers; RPC tests cover unlinking without deleting Telegram-owned publications or newer app links.
- The native repository also contains privileged `apps/api/functions/src/users.ts` Auth triggers. `createUser` writes a user document; `deleteUser` recursively removes owned studies and user data. Its `apps/api/.firebaserc` targets the legacy `bible-strong-app` project, and study-file helpers name that legacy storage bucket. Source presence is not proof those functions run in `cyberjudah-app`. Do not deploy or retarget them on that assumption. Confirm the actual CyberJudah function inventory and execution identities before declaring privileged-writer coverage complete.
- Payment callbacks and Telegram KV chat/reminder writers belong to Telegram's independent erasure acceptance. Native unlink preserves Telegram-owned records. Their presence does not authorize deleting that history or enabling Telegram's gate.
